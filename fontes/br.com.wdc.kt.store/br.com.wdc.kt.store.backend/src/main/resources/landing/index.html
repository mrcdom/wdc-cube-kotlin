WDC Store

A small shop — sign in, browse products, fill a cart, buy, see the receipt — written once with the Cube MVP framework in Kotlin Multiplatform. The screens' logic lives in shared presenters; each user interface below only paints what they show. Same app, same presenters, different technologies: pick one to try.

{{security-warning}}

In the browser

Two ways to split the work. In a remote view, the presenters run on this server and the page only paints and sends clicks. In a local view, the presenters run in the browser and fetch data through the REST API.

React · TypeScript

Remote view

The presenters run here, on the server; the page is a thin React client that paints the scopes it receives over a WebSocket and sends back what the user does. No business code reaches the browser.

  • presenters on the server
  • WebSocket
  • TypeScript

Choose it to see the thinnest client: logic and data stay on the server.

Open the React client

Not built. In remote.react.typescript, run npm install && npm run build, then restart the backend.

React · Kotlin

Remote view

The same server and protocol as the TypeScript client, with the page written in Kotlin (React through kotlin-wrappers) and compiled to JavaScript by the Kotlin toolchain itself.

  • presenters on the server
  • WebSocket
  • Kotlin/JS

Choose it to see a browser client with no TypeScript at all.

Open the Kotlin client

Not deployed. Run remote.react.kotlin/deploy.sh, then restart the backend.

Native web · Kotlin

Local view

The presenters — the same ones the mobile apps run — compiled to JavaScript and running in the page, with hand-written React views. Data comes from the REST API.

  • presenters in the browser
  • REST
  • Kotlin/JS

Choose it to see the shared presenters running in the browser.

Open the native web client

Not deployed. Run native.web/deploy.sh, then restart the backend.

Compose Multiplatform · Web

Local view

The very same Compose screens as the desktop, Android and iOS apps, compiled to WebAssembly and drawn on a canvas. The presenters run in the page; data comes from the REST API.

  • presenters in the browser
  • REST
  • Kotlin/Wasm

Choose it to see one UI codebase reach the web as well.

Open the Compose client

Not deployed. Run compose.web/deploy.sh, then restart the backend.

Outside the browser

The same presenters also run in apps; run them from fontes/:

  • Compose desktop — ./gradlew :view-compose-desktop:run
  • Compose Android and iOS, native Android (Views) and native iOS (UIKit) — the deploy.sh of each module

Under the hood

The REST API the local views use is described in /openapi.json. The source, with the architecture documents, is at github.com/mrcdom/wdc-cube-kotlin.
